07 왜 순서대로 배워야 하는가 The Order Matters

순서를 지켜야
길을 잃지 않습니다.

버전관리를 모르면 백업할 게 뭔지 모르고,
백업을 모르면 GitHub를 왜 쓰는지 모릅니다.

STEP 01 버전 관리
STEP 02 백업
STEP 03 협업
IF · 버전관리를 모르면
→ 무엇이 바뀌었는지 알 수 없다.
IF · 백업을 모르면
→ GitHub를 왜 쓰는지 모른다.
IF · 협업이 필요 없다면
→ Git을 쓸 이유 자체가 없어진다.
💡 “Git은 협업툴이 아니라, 버전관리툴입니다.”
08 Git 프로그램의 종류 도구 고르기

Git은 개념,
프로그램은 여러 가지.

Git은 ‘자동차’가 아니라 ‘자동차라는 개념’에 가깝습니다.
실제로 Git을 사용하려면 Git 클라이언트 프로그램 중 하나를 골라야 합니다.

CLI · 명령어

Git Bash

가장 기본. 터미널에 직접 명령어를 입력하는 방식.
한 번 익혀두면 어디서든 통합니다.
$ git add .
$ git commit -m "first"
$ git push origin main

VS Code 터미널

코드 편집 + Git 명령을 한 화면에서. 입문자에게 가장 추천하는 환경.

GitHub Desktop

명령어 없이 버튼 클릭으로 사용. 쉽지만, 고급 기능에선 한계가 옵니다.

09 한 걸음 더 · Branch 보너스 핵심

브랜치는
평행 세계다.

main = 현실 세계 · 기본 작업 공간
branch = 평행 세계 · 실험용 복사본

실패해도 main은 그대로. 성공하면 main에 합치면 됩니다.

master → main ‘master / slave’가 노예 제도를 연상시킨다는 이유로 최신 Git에서는 main을 사용합니다.
$ git branch feature-login
$ git checkout feature-login
# 실험 → 성공하면 →
$ git merge feature-login
METAPHOR
main = 현실
vs.
METAPHOR
branch = 평행 세계
브랜치를 ‘복사본’이 아니라
‘평행 세계’로 이해하세요.
